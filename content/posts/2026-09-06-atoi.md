Вы когда-нибудь задумывались, как работает преобразование строки в число в go? 

Я задумалась об этом вчера, когда решала [задачку c LeetCode](https://leetcode.com/problems/string-to-integer-atoi).  
Потому что первое, что приходит в голову, когда нужно сделать преобразование - использовать `strings.TrimSpace + strconv.Atoi`.  
Но, есть ощущение, что авторы задачи ждали от меня не этого :D  
Поэтому я решила тихонечко подсмотреть, как выглядит парсинг без стандартной библиотеки.  
А вернее, внутри неё, в самой `strconv.Atoi`.   

Функция довольно небольшая, и для моего случая требуется только первая часть, с быстрым парсингом:
```go
// go/src/internal/strconv/atoi.go

func Atoi(s string) (int, error) {
// Константа для формирования красивых ошибок, 
// на случай, если что-то пойдёт не так
	const fnAtoi = "Atoi" 

	// 1. Быстрый парсинг для небольших чиселок (int32 и int64)
	// 1.1 Проверка разрядности и длины строки для паарсинга
	sLen := len(s)
	if intSize == 32 && (0 < sLen && sLen < 10) ||
		intSize == 64 && (0 < sLen && sLen < 19) {
		// 1.2 Исходная строка сохраняется, чтобы дальше 
		// безопасно работать с ведущим знаком числа
		s0 := s
		// 1.3 Обработка знака числа - пока он просто обрезается
		if s[0] == '-' || s[0] == '+' {
			s = s[1:]
			if len(s) < 1 {
				return 0, ErrSyntax
			}
		}
		// 1.4 Начинается сбор результирующего числа
		n := 0
		// 1.5 Ранжируемся по байтам строки.
		// Если что, при переводе строки в слайс байт при range  
		// не происходит аллокаций, потому что компилятор умный,
        // он понимает, что строка - это и есть слайс байт
		for _, ch := range []byte(s) {
			// 1.6 Из номера текущего числа вычитаем номер '0' 
            // по таблице ASCII ('0' это 48)
			// https://www.asciitable.com
			// Например, для тройки номер в таблице = 51
			// '3' - '0' = 51 - 48 = 3
			// По-моему, очень красиво. Это моя любимая часть ^—^
			ch -= '0'
			// 1.7 Проверяем, что строка содержит только числа
			if ch > 9 {
				return 0, ErrSyntax
			}
			// 1.8 Это вторая любимая часть :)
			// Увеличивается разрядность имеющегося числа, 
			// перед тем, как присоединить к нему следующее
			n = n*10 + int(ch)
		}
		// 1.9 Если ведущий знак был '-', то добавляем его к числу. 
		// Интересный синтаксис, не знала, что так можно О_о
		if s0[0] == '-' {
			n = -n
		}
		// Возврат результирующей чиселки
		return n, nil
	}

	// 2. Медленный парсинг для больших чисел:
	i64, err := ParseInt(s, 10, 0)
	return int(i64), err
}
```

Просто? Просто!  
Красиво? Ещё как😍  
И даже есть пара инсайтов:
1. Оказывается, что `strconv.Atoi` умеет парсить числа с ведущим знаком `+`, что вообще-то логично, но непонятно, зачем :D
```go
fmt.Println(strconv.Atoi("+42"))
// 42 <nil>
```
2. Оригинальный комментарий ко второму блоку функции (где парсятся большие числа) выглядит так:
```go
// Slow path for invalid, big, or underscored integers.
i64, err := ParseInt(s, 10, 0)
return int(i64), err
```
Из-за этого можно подумать, что  `strconv.Atoi` может распарсить число, написанное через нижнее подчёркивание.  Но нет: 
```go
fmt.Println(4_2)
fmt.Println(strconv.Atoi("4_2"))
// 42
// 0 strconv.Atoi: parsing "4_2": invalid syntax
```
Всё-таки, правила компиляции отличаются от правил парсинга чисел.  
Нижние подчеркивания действительно распарсятся, но только при использовании `strconv.ParseInt` напрямую, и при системе счисления 0: 
```go
fmt.Println(strconv.ParseInt("4_2", 0, 32))  // зануляем базу числа, всё работает
fmt.Println(strconv.ParseInt("4_2", 10, 32)) // в десятичной системе получаем ошибку
// 42 <nil>
// 0 strconv.ParseInt: parsing "4_2": invalid syntax
```
3. Момент с сохранением всей строки для обработки ведущего знака `s0 := s` не выглядит оптимальным. Как будто, его можно использовать только в том случае, когда знак существует.
